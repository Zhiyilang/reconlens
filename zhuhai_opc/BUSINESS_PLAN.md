## 一、项目摘要

ReconLens 是一款面向代理记账机构与中小微企业财务部门的**对账差异解释引擎**。

市面上的对账工具都停在同一步：输出一张"未匹配清单"。那不是结果，是一张待办
清单——对账真正的成本不在**找出**差异，而在**解释**差异，而这一步今天仍由财务
人员逐条手工完成。

ReconLens 攻的是后半段。它对每一条残差给出**明确的归因**，并附上：

- **证据链**：有序、带权重、注明来源的可观测事实
- **反证**：它选择推翻的那些事实，如实保留
- **置信度**：由证据权重机械推导，任何人可以重算，禁止人工微调
- **诚实边界**：无证据支撑时输出 `UNEXPLAINED`，绝不猜测

产品采用 Python 标准库实现，**零第三方依赖**，可以完全私有化部署在企业内网——
这对财务数据不出内网的合规要求是决定性优势。

**当前状态**：产品已完工，`python eval.py` **129 条断言全绿**，含敌意 locale 子进程
与非 UTF-8 控制台两项健壮性验证。商业模式待验证，寻求首批种子客户。

### 2.2 为什么现在是窗口期

1. **金税四期落地 + 全电发票全国推广**：发票电子化、数据自动比对，"账、票、货、资金流
   闭环"成为硬性要求，对账从"期末可选动作"变成"经常性合规动作"。
2. **人力成本刚性上涨**：熟练会计月薪七、八千元起步，而 99 元 / 199 元的低价代账套餐
   满天飞——行业陷入"降价—客户流失—再降价"的死循环，倒逼机构用工具替代重复人力。
3. **AI 已被行业验证可行**：据上市财税数字化企业（税友股份）对外披露，传统工具条件下
   单人每月处理简单账务最高覆盖 270 家；接入 AI 能力后单人每月可达 800 余家，人效提升
   一倍以上。这说明**市场教育已经完成，客户愿意为 AI 提效付费**。

### 2.3 目标客户

**第一梯队：代理记账机构**（尤其是服务 50–500 家客户的腰部机构）
- 痛点最直接：账单数量大、毛利率薄、会计流动率高
- 采购决策链短，单个老板即可决定
- 财政部口径 16 万家，广东省 2.6 万家

**第二梯队：中小微企业财务共享中心 / 集团资金结算岗**
- 银行流水与内部账的日常核对是固定工作量
- 对"财务数据不出内网"有强诉求 → 私有化部署是刚需

**第三梯队（区域性机会）：珠澳跨境结算相关主体**
- 横琴粤澳深度合作区背景下，珠澳之间存在频繁的跨境收付与多币种结算
- 多币种 + 时差导致的挂账差异，正是 ReconLens `CURRENCY_MISMATCH` 与
  `DATE_MISMATCH` 两类归因已覆盖的场景

## 三、痛点与技术差异化

### 3.1 现有方案的断点

| 现有工具做到 | 留给人工的 |
|---|---|
| 找出哪些条目对不上 | 为什么对不上 |
| 给出金额差额 | 这笔差额是手续费、在途、还是录入错误 |
| 支持自定义匹配规则 | 规则失效时无人知道边界在哪 |

这一步"为什么"无法跳过，因为对账结论最终要签字、要经得起审计追溯。

### 3.2 ReconLens 的技术答案

**① 确定性级联匹配**（而非全局最优）
匹配分四阶段，由紧到松，前一阶段消费掉的条目绝不被后一阶段重取：

```
EXACT_REF          → 凭证号 + 金额同时一致（黄金标准）
EXACT_AMOUNT_DATE  → 金额 + 日期一致
AMOUNT_DATE_WINDOW → 金额一致，日期 ±N 天（清算在途）
SPLIT_OR_MERGE     → 单边 ≤3 笔之和等于对方 1 笔（拆单/合并）
```

**为什么不用匈牙利算法求全局最优？** 因为全局最优无法回答"为什么是这一对"。
而每一笔匹配最终都可能被审计追问，可解释性优先于最优性。

**② 十条归因分类 + 证据/反证记账**

| 归因 | 典型场景 |
|---|---|
| `FEE_DEDUCTION` | 800 元入账、795 元到账，缺 5 元且在手续费特征区间内 |
| `DATE_MISMATCH` | 金额完全一致，日期相差 15 天 —— 清算在途或期末截止差 |
| `AMOUNT_MISMATCH` | 同日、金额确实不同 —— 需人工决策 |
| `SPLIT_OR_MERGE` | 银行一笔 2 万，账本两笔 1.2 万 + 8 千 |
| `DUPLICATE` | 同日同额出现两次 —— 重复记账 |
| `CURRENCY_MISMATCH` | 只有经由汇率换算才一致 |
| `MISSING_IN_LEDGER` / `MISSING_IN_BANK` | 单边存在 |
| `UNEXPLAINED` | **诚实输出，绝不猜测** |

**③ 三条硬保证**

- **金额零误差**：一律以整数最小单位（分）存储，解析使用 `Decimal` + `ROUND_HALF_UP`。
  浮点无法表示 `0.1`，而"半分钱静默消失"正是对账领域最不能接受的事故。
- **守恒律**：已匹配条目数 + 残余条目数 == 总条目数，两侧强制成立。
  对账引擎最坏的失败是某条记录无声无息地消失。
- **跨币种隔离**：未显式提供汇率时，不同币种绝不互相等式化。100 元不等于 100 美元。

### 3.3 競爭與壁壘

| 对手类型 | 其形态 | ReconLens 的位置 |
|---|---|---|
| 头部财税 SaaS（用友、金蝶、税友等） | 全链路平台，云化 | 不正面竞争。作为其能力补丁，专注"差异归因"单点做到可审计 |
| Excel 手工 / VBA 宏 | 零成本但不可复用 | 直接替代，且输出可追溯的证据链 |
| 通用 LLM 直接问答 | 能说原因但不可复现 | **确定性优先**：LLM 不可复现、不可审计，且数据须出网 |

**核心壁垒不是算法复杂度，而是两点**：
1. 一件Reasoning為了驗證 — 每条判定都必须挂证据链，这个约束反过来决定了架构
2. 零依赖可私有化 —— 财务数据不出内网，这是准入资格而非加分项

## 四、商业模式

### 4.1 定价

| 形态 | 目标客户 | 价格档位 |
|---|---|---|
| 私有化授权（一次性 + 年度维护） | 腰部代账机构、有合规要求的集团 | 3–8 万元 / 年 / 机构 |
| SaaS 订阅（按账套数分档） | 中小微企业财务部门 | 300–1,500 元 / 月 / 账套 |
| 定制接入（一次性交付） | 有自有系统的中大型客户 | 按项目议价 |

### 4.2 单位经济（OPC 模式的成本优势）

产品零第三方依赖、单人即可完成研发交付与运维，**无服务器账单、无模型调用费**。
主要成本仅为：

- 交付与售后支持时间
- 少量市场推广

这意味着在同等定价下毛利率显著高于依赖云 API 的同类产品，可以在早期用
更低的试用地进入市场。

### 4.3 获客路径

1. **行业社群切入**：代理记账行业有成熟的协会、博览会（代博会）与区域联盟生态，
   单点突破后容易通过口碑向同类机构扩散
2. **内容获客**：公开技术方法论（已有完整文档），建立"懂财务、也懂审计"的专业信任
3. **区域落地**：依托珠海 / 广东的代理记账集群（持证机构约 2.6 万家）做地推试点

## 五、OPC（一人公司）模式的适配性说明

本次大赛要求"项目需以 OPC 模式开展"。ReconLens 不是把一个团队项目压缩到一个人，
而是**从第一行代码起就按单人可交付的方式设计**：

| 维度 | 传统团队方式 | 本项目 OPC 方式 |
|---|---|---|
| 技术栈 | 微服务 + 依赖众多 | 零第三方依赖，标准库 |
| 运维 | 需要 SRE 值守 | 无服务、无调用费，客户侧运行 |
| 交付 | 实施团队驻场 | 单文件包 + Markdown/JSON 输出，可自助接入 |
| 验证 | 依赖 QA 团队 | **`eval.py` 129 条断言自证**，含敌意 locale 验证 |
| 现金流 | 需要融资养团队 | 单人成本极低，可自举到盈亏平衡 |

**单人公司真正的杠杆在于：把重复劳动固化进代码。本项目本身即是这一方法论的
产物——产品开发全流程由 AI Coding 完成（详见 `AI_CODING_JOURNEY.md`），
一个人即可维持整套研发与交付闭环。**

   387 亿元。计划以珠海为原点，先服务本地 20–30 家腰部机构验证单元模型，再向
   广深莞佛扩散。

5. **算力与模型支持**：后续若引入模型能力处理非结构化票据，可申请"算力券"
